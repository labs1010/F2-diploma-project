# ВСТУП

## Актуальність теми

Тестування REST API передбачає багаторазове виконання HTTP-запитів, зіставлення фактичних відповідей з очікуваними результатами та фіксацію відхилень. За ручного виконання цих операцій повторні перевірки після змін програмного інтерфейсу потребують відтворення однакових дій. Відсутність формалізованого опису кроків і єдиної історії запусків ускладнює простежуваність та порівняння результатів тестування.

Особливої уваги потребують сценарії з взаємозалежними REST API-операціями, коли значення з JSON-відповіді одного запиту використовується в наступному. Наприклад, після створення ресурсу запитом POST його ідентифікатор необхідно передати до GET, перевірити HTTP-статус, поля JSON і тривалість відповіді та зафіксувати результати кожного кроку. Проєктування механізму послідовного виконання таких сценаріїв, контрольованої обробки помилок і збереження історії є актуальним інженерним завданням. Кількісні переваги запропонованого рішення підлягатимуть оцінюванню лише після реалізації та випробувань.

## Об'єкт дослідження

Процес сценарного тестування взаємозалежних REST API-операцій, що охоплює формування послідовності HTTP-запитів, їх виконання, перевірку відповідей і фіксацію результатів.

## Предмет дослідження

Методи та алгоритми опису і послідовного виконання HTTP-сценаріїв із передаванням значень із JSON-відповідей між кроками; способи перевірки HTTP-статусів, JSON-полів і часу відповіді; архітектурні рішення модульного моноліту та засоби C#/.NET, ASP.NET Core, Blazor, Entity Framework Core і PostgreSQL для реалізації, збереження й аналізу результатів.

## Мета роботи

Проєктування та розроблення системи автоматизованого сценарного тестування REST API з аналізом результатів для забезпечення відтворюваного послідовного виконання залежних HTTP-запитів, формалізованої перевірки відповідей, збереження історії запусків і простежуваного представлення результатів у вебінтерфейсі.

## Завдання проєкту

1. Проаналізувати процес сценарного тестування REST API, наявні інструменти й обмеження ручного виконання взаємозалежних HTTP-операцій.
2. Обґрунтувати функціональні та нефункціональні вимоги, вибір технологій C#/.NET, ASP.NET Core, Blazor, Entity Framework Core, PostgreSQL і засобів тестування.
3. Спроєктувати модульну монолітну архітектуру, модель даних та UML/C4-представлення основних компонентів і взаємодій.
4. Розробити алгоритми впорядкування й послідовного виконання HTTP-кроків, вилучення та передавання значень JSON і перевірки відповідей з урахуванням таймаутів та помилок.
5. Реалізувати та інтегрувати керування сценаріями, механізм виконання, модуль перевірок, збереження історії й відображення результатів у вебінтерфейсі.
6. Перевірити реалізовані компоненти модульними та інтеграційними тестами xUnit, дослідити поведінку типових і помилкових сценаріїв та оцінити результати за визначеними критеріями.
7. Систематизувати результати проєктування й випробувань у пояснювальній записці та підготувати матеріали для науково-практичної апробації відповідно до вимог освітньої програми.
